# Reconcile throttle-resilience proof

Production run 31634514031-era evidence showed `inspected_targets=3`, `skipped_targets=125`, and `recovered_targets=0` after one `http_403` plus two attributed `not_inspected_abort` targets. At the same time, the `repository_actions` pool was under sustained pressure (`item_metadata` read throttle first=718, repeat=1197; roughly 6,000 `artifact_download` circuit skips) while the `target_app` pool was nearly idle.

The code investigation found that parked REST checks, standard REST checks, and batched GraphQL canonical discovery all selected `GITHUB_TOKEN`. In the scheduled workflow that variable was `${{ github.token }}`, the same repository Actions credential used by the prior-artifact download and stuck-run Actions API remediation. Round 1 moved those reads to one OpenClaw installation token, which would have failed every target owned outside that installation.

The owner decision preserves cross-owner recovery. The operator now reuses the Worker's canonical GitHub App plumbing—`githubAppCredentials`, `signGithubAppJwt`, `githubAppInstallationId`, and `createGithubAppTokenFor`—to mint a read-only contents/issues/pull-request token for each target owner. Successful tokens and setup-throttle rejections are cached per owner for the cycle, while `installation_missing` rejections are cached per repository so a selected-repositories installation can still reach an accessible sibling repository. GraphQL batches are owner-homogeneous. A genuinely missing or revoked installation is a per-target `installation_missing` skip with a bounded sample; it never aborts the cycle. Repository artifact and Actions-run operations remain on `${{ github.token }}`.

Round 4 closes the rollout boundary: the operator defaults target reads to `github-app` mode and validates the App ID/private-key pair synchronously at startup. A missing ID, missing key, or missing pair is a hard error naming exactly the absent field. The repository Actions token is usable for target reads only through the explicit `EXACT_REVIEW_TARGET_TOKEN_MODE=actions` opt-in. Both checked-in operator workflows select `github-app`, and the scheduled steps pass the referenced private-key secret; the repository currently exposes that secret name.

The original abort came from https://github.com/openclaw/clawsweeper/pull/973: complete canonical-alias discovery protected active sibling fences and bounded API usage before mutation. https://github.com/openclaw/clawsweeper/pull/1117 added honest per-target diagnostics while deliberately retaining that behavior. The new policy changes only GitHub-confirmed rate-limit or abuse 403s and all 429s: isolated target-read and App-setup throttles become per-target or per-owner skips, a successful target read resets the counter, and three consecutive throttled calls abort the remaining phase. A cached setup rejection may skip many targets or GraphQL batches but counts as the one GitHub call that was actually throttled. App-setup skips carry `github_throttled scope=app_setup` with the stage, owner, and status. Authorization failures, policy 403s, and every other non-throttle discovery failure still use the conservative abort path. The existing target, recovery, GraphQL batch, terminal-recheck, and inventory caps remain intact.
