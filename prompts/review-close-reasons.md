External means a non-`OWNER`/`MEMBER`/`COLLABORATOR` author; maintainer engagement means an assignee, requested reviewer, or maintainer comment or review; automation labels are `clawsweeper:human-review`, `clawsweeper:manual-only`, `clawsweeper:autofix`, and `clawsweeper:automerge`.

- `implemented_on_main`: current `main` fixes the request well enough, even without the proposed workflow, file split, or names; main-only counts. Verify the behavior in source (and tests/docs), then trace the fix from a merged `closingPullRequests` or `referencingMergedPullRequests` entry to its commit, timestamp, and first release (`git tag --contains <sha>`, the changelog, `gh api repos/<owner>/<repo>/releases`) or current-main-only status. Evidence: source entries with `file` and `sha`, a git blame/log/show provenance entry, and that release check; without `fixedSha` and `fixedRelease` or `fixedAt` backed by it, keep open, and invent no release facts. A main-only close comment says fixed on current `main` with `fixedAt`. For a PR, source resemblance, an overlapping feature, or a main commit never suffices for this or `mostly_implemented_on_main`: cite a GitHub-verified, merged, same-repository fixing PR that GitHub formally links to the request with an explicit connection to the requested behavior; when that link is incomplete, ambiguous, cross-repository, or inferred, keep the PR open and close no linked issue (a linked issue is neither permission nor proof to close either).
- `mostly_implemented_on_main`: a PR older than 60 days whose central useful change is on `main` under the same provenance standard, when main covers most but not every line. The leftover is minor, obsolete, risky churn, style-only, superseded, or tracked elsewhere, with no recent substantive human response that changes the decision; keep open when a meaningful unique fix, feature, hardening, test, doc, migration, or product decision remains. The close comment says what is on `main`, why the leftover does not matter, and why the stale branch is not useful.
- `cannot_reproduce`: a reasonable reproduction on current `main` fails, or the report no longer matches current behavior. Separate missing reporter evidence from a mechanism source disproves: search the whole tree, history, renamed paths, and the shipped version, and trace the owner, callers, dependency contract, and regression tests. When the named implementation never existed or cannot do the alleged operation and the real code or tests disprove the failure, close with high confidence on that evidence, with no request for screenshots, logs, or maintainer follow-up; repeated reports about nonexistent files close when each claim is disproved. Keep open while an affected shipped version, real source path, observed failure, or dependency behavior is unverified.
- `clawhub`: a useful idea that belongs as a ClawHub skill/plugin rather than core (`VISION.md` is the scope anchor): optional integration, provider, channel, skill, bundle, MCP, or plugin-discovery work that current extension surfaces support, without a missing API or protected maintainer signal. An OpenClaw PR that only adds bundled skills under `skills/<vendor>/**` is `itemCategory: "skill"` and, with high confidence, `clawhub`: ask the contributor to upload or publish it through ClawHub.com. Keep open for a bundled-core regression, missing plugin API, security/core hardening, or clear product call. `bestSolution` and `closeComment` are a self-serve handoff that links an already-posted plugin and names the package shape (skill, plugin, provider, channel, bundle, MCP integration); the host appends the packaging checklist and states that ClawSweeper opens no ClawHub issue or PR and publishes nothing.
- `duplicate_or_superseded`: another issue or PR tracks the same remaining work or clearly supersedes this one. Read and link it, set `rootCauseCluster.canonicalRef` to it (an empty one keeps a PR open), and say whether it is open, closed, merged, or shipped. In a same-root-cause cluster keep one canonical issue open and close satellites whose unique logs, platforms, or context the comment preserves by link; unique evidence blocks the close only when it implies a distinct root cause, platform fix, or remaining behavior. A replacing PR is merged, or open, proof-positive, and safely landable; keep this PR open when the replacement is closed unmerged, unproven, F-rated, proposed for close, or not cleanly mergeable.
- `low_signal_unmergeable_pr`: the branch may hold a small useful idea but is net-negative: most of the diff is unrelated, copied, generated, bloated, incoherent, or against the repository's structure. Keep open when meaningful unique work can be repaired keeping most of the branch, maintainers asked to adopt it, a protected label or maintainer author needs judgment, or the only gaps are tests, style, or review follow-up; missing proof alone on an idle low-rated PR is `stalled_unproven_pr`. The comment credits the useful part, names the unmergeable diff, and invites a narrow new PR.
- `stalled_unproven_pr`: an external PR whose proof ask expired: proof `missing`, `mock_only`, or `insufficient`; `overallTier` D or F; at least 14 days old with no commit or check activity for 14 days; a `status: 📣 needs proof` or `triage: needs-real-behavior-proof` label or proof-nudge comment at least 14 days old; no maintainer engagement or automation label. Not for drafts (`abandoned_pr`), minor follow-up on a well-rated patch, or a `proof: sufficient`/`proof: override` label. The comment names the missing proof kind and invites reopening with real-behavior proof (a live run, logs, a validation transcript).
- `author_pr_budget_exceeded`: propose only when the context states the author's open-PR count above the configured budget (never search for it; apply-side promotion is the normal path), for an external PR at least 7 days old with commit, status, or check activity at least 7 days old, rated D or F or with proof `missing`, `mock_only`, or `insufficient`; never for an S/A/B PR with sufficient or overridden proof, a protected or auto-close-exempt label, or maintainer engagement. The comment states the count and budget, says closing or finishing other PRs frees budget, and invites reopening under budget or with real proof.
- `abandoned_pr`: an external PR at least 30 days old with no commit or check activity for 30 days that is stalled: draft, `status: ⏳ waiting on author`, failing checks, or not cleanly mergeable on its head. Not for S/A/B work with sufficient or overridden proof (repair/adopt instead), maintainer engagement, or an automation label. The comment credits the work, states the inactivity and stalled state, and invites a rebased reopen or fresh PR with green checks.
- `unconfirmed_product_direction`: an external, correct, well-proven PR adding feature or configuration surface without maintainer-confirmed direction: `itemCategory` `feature`; `requiresProductDecision` and `requiresNewFeature` or `requiresNewConfigOption` true; `patch is correct` with no findings; security `cleared` with no concerns; proof sufficient or overridden; quality C or better; no automation label. Not for bugs with an established contract, security-sensitive work, weak patches, or work maintainers already calibrated. Explain that quality is separate from product acceptance and a maintainer can sponsor, narrow, or reopen the direction.
- `unsponsored_feature_request`: an issue older than 90 days requesting a feature that awaits a maintainer product decision: `itemCategory` `feature`; `requiresProductDecision` true; `maintainerDecision.required` true with `kind: product_direction`; no maintainer engagement (assignee, milestone, maintainer comment), no human comment in 60 days, no linked open PR. Not for bugs, strong community traction, `clawsweeper:linked-pr-open`, or any label whose normalized name contains `security`. The comment parks a reversible idea, not a rejection: no maintainer has confirmed the direction, a qualifying maintainer can reopen it by commenting `@clawsweeper revive` or the configured positive-reaction threshold reopens it automatically; mention ClawHub when relevant.
- `stale_version_bug`: an issue-only bug at least 120 days old tied to a clearly outdated version/build or a code path visibly changed on `main`, with no reproduction on a recent release, no maintainer engagement, no protected label, and no label whose normalized name contains `security`. The comment names the reported version (or age), says the code changed substantially, asks for a retest on the current release, and promises reopening on a fresh current-version reproduction.
- `obsolete_fix_pr`: a fix PR at least 90 days old, head activity at least 30 days old, at most five changed files, every touched path substantially rewritten or removed on `main` after the head commit (a CI/workflow fix qualifies when that workflow was rewritten or deleted); no maintainer engagement or protected label. An S/A/B PR with sufficient or overridden proof qualifies only when evidence proves every touched path changed or gone. The comment credits the work, names the changed or vanished files, and invites a fresh PR against `main` if the problem still reproduces.
- `not_actionable_in_repo`: the action belongs outside this repository: project administration, external hosting or third-party services, domain/account ownership, a separately distributed product's renderer/provider/client, or historical cleanup code or docs cannot fix. Verify ownership against the source tree and official release/docs boundaries; QClaw `0.x` desktop/client reports, `qclaw/*` providers, QClaw renderer logs, and externally maintained WeChat adapters are ownership signals, not OpenClaw bugs. Unless the report reproduces on an official OpenClaw release or identifies a concrete upstream OpenClaw defect, close now with high confidence, name the external owner, and set `workCandidate: "none"`; missing private or third-party traces are no reason for `manual_review`, `maintainerDecision.required`, or `clawsweeper:needs-maintainer-review`. Keep open only for a demonstrated failure in an official release or owned source path, a missing core extension API, or another reproducible upstream defect; healthy owned source paths, generic fallback/delivery plumbing, or a hypothetical upstream boundary demonstrate none. Setup/support, one-line, screenshot-only, or credential-redaction reports qualify when code/docs show expected or externally configured behavior and no source-level reproduction exists. The comment asks for credential rotation when relevant and names the diagnostic command, docs page, or external owner.
- `incoherent`: after reading title, body, comments, and any diff, the item still names no coherent testable problem, owned behavior, or useful bounded contribution (missing essential context, contradictory claims, empty or generated content, a purposeless patch). Close courteously and invite reopening with an official OpenClaw version, affected component, reproduction, expected/actual behavior, or a focused patch.
- `stale_insufficient_info`: an issue older than 60 days that cannot be verified against current `main` (missing reproduction data, or a significantly outdated version or behavior whose code materially changed), with no human reproducing it on a current version in 60 days. Check current code/docs for a known fix first; a clear remaining feature, configuration surface, security hardening request, or product decision stays open whatever its age. The comment asks for a new issue with current reproduction steps, expected/actual behavior, logs, versions, and config.
